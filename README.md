# 探索アルゴリズム可視化

探索アルゴリズムの動きをブラウザ上でステップごとにアニメーション表示する Web ページです。
依存ライブラリ・ビルド不要の素の JavaScript で実装しています。

## 使い方

`index.html` をブラウザで開くだけで動作します。

ローカルサーバーで開く場合:

```sh
python3 -m http.server 8000
# http://localhost:8000 を開く
```

### 共通操作

| 操作 | 内容 |
|---|---|
| タブ | 経路探索 / 配列探索 / 焼きなまし法 を切り替え |
| アルゴリズム | 実行するアルゴリズムを選択 |
| 実行 / 一時停止 / 再開 | アニメーションの開始・停止 |
| 1ステップ | 1手ずつ進める |
| リセット | 探索結果をクリア（盤面・配列・地形はそのまま） |
| 速度 | 1〜10 の10段階 |

キーボードショートカット: `Space` 実行/一時停止、`→` 1ステップ、`R` リセット

右側のパネルにアルゴリズムの解説と統計情報が表示されます。

## 収録アルゴリズム

### 経路探索（グリッド）

| アルゴリズム | 優先する基準 | 最短経路の保証 |
|---|---|---|
| 幅優先探索 (BFS) | スタートからの手数 | ○（重みは無視） |
| 深さ優先探索 (DFS) | 最後に見つけたマス | × |
| ダイクストラ法 | 累積コスト g | ○ |
| A* 探索 | g + h（h: マンハッタン距離） | ○ |
| 貪欲最良優先探索 | 推定コスト h | × |
| ビームサーチ | 各深さで h の上位 k 個のみ残す | ×（ゴールを見逃すこともある） |

- ドラッグで **壁** / **重み（通過コスト5）** を描画、**消去** で削除
- `S`（スタート）と `G`（ゴール）はドラッグで移動
- 迷路生成（再帰的バックトラック＋一部の壁を除去してループを作成）、ランダム壁、ランダム重み、盤面クリア
- ビームサーチ選択時はビーム幅（1〜10）を指定可能
- 統計: 訪問ノード数、経路長（手数）、経路コスト

### 配列探索

| アルゴリズム | 前提 | 計算量 |
|---|---|---|
| 線形探索 | なし | O(n) |
| 二分探索 | ソート済み配列 | O(log n) |

- 要素数（8〜64）、探す値、ソート有無を変更可能（二分探索選択時は自動でソート）
- 二分探索では探索範囲の下端・中央・上端を `L` / `M` / `H` で表示
- 各比較の内容をログ表示
- 統計: 比較回数、最悪比較回数

### 焼きなまし法（1次元関数の最小化）

| アルゴリズム | 受理ルール |
|---|---|
| 焼きなまし法 | 改善なら必ず受理、悪化なら確率 `exp(-ΔE / T)` で受理。毎反復 `T ← T × 冷却率` |
| 山登り法（比較用） | 改善のみ受理 |

- 目的関数は複数の正弦波＋二次関数を組み合わせた多峰性の地形（値は 0〜100 に正規化、最小値 = 0）
- 初期温度、冷却率、近傍の幅（候補を生成する正規分布の標準偏差）を調整可能
- 反復回数は温度が 0.01 に下がるまでの回数。山登り法も同じ回数で実行
- 地形グラフのクリックで開始点を変更、「地形を変更」で関数を再生成
- 下段のグラフで現在値・最良値・温度の推移を表示
- 統計: 反復回数、温度、現在値、最良値、悪化を受理した回数、直近の受理確率

## ファイル構成

```
.
├── index.html
├── style.css             # ライト/ダークテーマ対応
└── js/
    ├── util.js           # Canvas・乱数などのヘルパー
    ├── runner.js         # アニメーション制御
    ├── algorithms.js     # 全アルゴリズムの実装
    ├── grid-view.js      # 経路探索タブ
    ├── array-view.js     # 配列探索タブ
    ├── anneal-view.js    # 焼きなまし法タブ
    └── main.js           # タブ切り替え・共通操作
```

`file://` で開けるよう、ES Modules ではなく通常の `<script>` で読み込んでいます（読み込み順に依存）。

## 仕組み

各アルゴリズムは **generator 関数** で実装しており、1ステップごとに `yield` で状態を返し、`return` で最終結果を返します。

```js
*bfs(g) {
  // ...
  yield { visit: cur, frontier };   // 1ステップ分の情報
  // ...
  return { path };                  // 最終結果
}
```

`Runner` が generator を速度に応じて進め、各ビューに渡します。各ビューは次のインターフェースを持ちます。

| メソッド | 役割 |
|---|---|
| `algorithms` | 選択肢（`id`, `label`, `desc`）の配列 |
| `createGenerator(id)` | 現在の設定で generator を生成 |
| `applyStep(step)` | `yield` された値を表示状態に反映 |
| `finish(result)` | `return` された最終結果を反映 |
| `clearVisual()` | 探索結果をクリア |
| `draw()` | 描画 |
| `stats()` | 統計 `[ラベル, 値]` の配列 |
| `onShow()` / `onAlgorithmChange(id)` | タブ表示時・アルゴリズム変更時の処理 |

### アルゴリズムを追加するには

1. `js/algorithms.js` に generator 関数を追加する
2. 対象ビューの `algorithms` 配列に `{ id, label, desc }` を追加する
3. 必要なら `createGenerator` で呼び出しを分岐させる

## 動作環境

モダンブラウザ（Chrome / Edge / Firefox / Safari の最新版）。`CanvasRenderingContext2D.roundRect` と `ResizeObserver` を使用しています。
